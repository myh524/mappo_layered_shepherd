# 项目可行性分析与删减计划

## 一、项目可行性分析

### 你的构想架构

```
羊群状态信息 ──→ 高层决策控制器 ──→ 站位参数 ──→ 采样 ──→ n个位置 ──→ 低层控制器 ──→ action
    │                  │                    │
    │                  │                    │
    ▼                  ▼                    ▼
质心、形状         理想站位半径、        位置坐标
主方向、扩散度     半径标准差、
                  聚集角度均值、聚集度
```

### 可行性评估：**高度可行** ✅

**理由：**

1. **MAPPO算法适配性强**：当前项目使用MAPPO（Multi-Agent PPO），非常适合多智能体协同任务

**输入输出维度灵活**：高层控制器输入（羊群特征）→输出（站位参数）的维度可自定义

**图神经网络支持**：项目已有GraphMPE支持，可用于处理羊群-机械狗的图结构关系

1. **模块化设计**：算法、环境、训练循环解耦，便于改造

**关键改动点：**

* 输入空间：从当前的agent/goal/obstacle位置 → 羊群状态特征

* 输出空间：从离散/连续动作 → 站位参数（连续值）

* 奖励函数：从导航奖励 → 羊群引导效果奖励

## 二、代码删减计划

### 需要删除的目录/文件：

| 路径                                    | 原因                                 |
| ------------------------------------- | ---------------------------------- |
| `baselines/` 整个目录                     | 基线算法（MADDPG、QMIX、GPG、DGN等），不需要对比实验 |
| `onpolicy/envs/mpe/` 整个目录             | 与multiagent/重复的环境定义                |
| `onpolicy/runner/separated/` 目录       | 非共享策略runner，你的任务使用共享策略             |
| `onpolicy/algorithms/graph_*.py`      | 图网络版本（可选保留，看是否需要）                  |
| `onpolicy/utils/graph_buffer.py`      | 图网络buffer（可选保留）                    |
| `multiagent/custom_scenarios/` 中大部分场景 | 只保留navigation.py作为参考               |

## 三、后续开发流程

### 阶段1：环境改造（1-2周）

1. 创建新场景文件 `herding.py`
2. 定义羊群实体和状态特征
3. 实现羊群运动模型（简单的群集行为）
4. 设计观测空间（羊群质心、形状、主方向、扩散度）
5. 设计动作空间（站位参数）
6. 设计奖励函数（羊群引导效果）

### 阶段2：网络结构适配（1周）

1. 修改Actor网络输出维度（站位参数）
2. 修改Critic网络输入维度
3. 实现站位参数到位置的采样逻辑

### 阶段3：训练调试（2-3周）

1. 配置训练参数
2. 设计课程学习策略（从简单场景开始）
3. 调试奖励函数
4. 评估和迭代

### 阶段4：与低层控制器对接（1周）

1. 定义高层-低层接口
2. 实现站位采样到低层输入的转换
3. 端到端测试
